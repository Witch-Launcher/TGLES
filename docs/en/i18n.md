# Adding a language

Docs use Docsify's **one-folder-per-language** model, so a new language
needs no code changes — only new files.

## Steps (example: adding Japanese `ja`)

1. Copy the whole `docs/en/` folder to `docs/ja/` (keep file names).
2. Translate every `.md` file in `docs/ja/`, while **keeping**:
    - file names and heading structure,
    - text status badges `[PASS]` / `[FAIL]` / `[WARN]`,
    - internal links (rewrite `/en/` to `/ja/`).
3. Edit `docs/ja/_navbar.md` and `docs/ja/_sidebar.md`: translate labels,
   and add the new language link to all navbars (`_navbar.md`,
   `vi/_navbar.md`, `en/_navbar.md`, and every other language navbar).
4. Add placeholders in `docs/index.html`:
   `'/ja/': '...'` in both the `placeholder` and `noData` objects, plus
   `'/ja/': '_coverpage.md'` in the `coverpage` object (otherwise `/ja/`
   gets no cover hero).
5. List the language in `docs/README.md` (landing page).
6. Preview: `docsify serve docs`, open `/ja/` and check sidebar, navbar,
   search and cover.

## Conventions

- Docs are text-only, no stickers or illustrative images; table statuses
  use text badges `[PASS]` / `[FAIL]` / `[WARN]`.
- No hardcoded language names in `index.html` except the two search
  objects — everything else is folder-driven.
- Every language PR must preview three routes: `/`, `/xx/`, `/xx/minecraft`.
